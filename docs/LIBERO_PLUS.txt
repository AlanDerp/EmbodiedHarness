LIBERO-Plus deployment condition (2026-11-05)

Base: 1a063ef; native adapter: src/embodied_harness/adapters/libero_plus.py.
This condition uses RGB-D and OSC_POSE, not the official RGB VLA evaluation or the earlier ASPIRE LIBERO-Pro campaign.

The single Panda arm is named right. World EE poses use metres and WXYZ quaternions; gripper opening is 1=open, 0=closed. Joint-target commands are explicitly rejected. Native steps use the benchmark's OSC scaling, one control tick per host action, 20 Hz. The deployment action cap is 4000; ten initialization settling ticks are recorded separately. Harness skill/action/time limits continue to apply independently.

RGB and depth are from the same native observation, flipped together when the renderer uses OpenGL image convention. Depth becomes metric axial depth. Robosuite camera utilities provide calibrated optical extrinsics and intrinsics. Object-state and object poses are not exported. Native check_success is the only task-success authority.

scene_ref is a zero-based index into the actual selected task's initialization bank. Out-of-range indices are rejected; no modulo remapping. Virtual variant name, physical BDDL plus serialized initialization content forms the partition fingerprint, and duplicate contents cannot appear across partitions. Single-state tasks cannot supply three disjoint groups within one task and require a separately specified cross-variant partition; do not silently reuse a state.

Provisioner config selects backend=libero_plus; native-worker receives --backend libero_plus. Campaign config pins a distinct condition protocol (current: aspire-fixloop-libero-plus-rgbd-osc-typed-contract-v3) and native_protocol=libero-plus-native-provisioner-v1. RoboDojo remains the default for existing configs.

Server deployment: /mnt/nimloth/benchmark-envs/embodied-harness.
Host .venv and native .venv-native are separate. The latter currently reads existing Python 3.12 third-party dependency packages through a .pth file; changing those shared dependencies can affect this deployment. Harness, SAM3 and robosuite sources are staged under this deployment; large LIBERO-Plus assets are a read-only-use symlink to the previously downloaded asset directory. Do not remove the asset source. No ASPIRE or Dual Loop policy/runtime code is imported.
